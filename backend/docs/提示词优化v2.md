# 提示词优化 v2

实施日期：2026-11-16。策略：学习练习、五维加权总分、追问独立评分、允许 JD 技能题、本轮只出技术题。

## 行为变化

| 环节 | v2 行为 |
| --- | --- |
| 解析 | 区分简历自述与 JD 要求；为 JD 核心要求摘录依据；跨页合并、冲突留痕，不将参与升级为主导 |
| 出题 | 类别限项目经验、专业能力、场景解决；JD 独有技能可问概念或假设场景，不预设项目经历；每题必须引用有效依据 |
| 评分 | 正确性40%、完整性20%、逻辑性20%、深度15%、清晰度5%；只由五维重算总分，取消要点覆盖率覆盖总分 |
| 追问 | 一次只追一个方向，返回问题及1–3条独立评分要点；不再继承主问题全部要点；不生成结束标记 |
| 上下文 | 评分和追问均能读取当前主问题及其历史问答；历史仅解释上下文，不重复计分；换主问题清空，恢复时从正式记录重建 |
| 输入边界 | 材料、回答、历史输出中指令不改变系统规则；讨论注入关键词本身不会触发零分 |

五维分数必须齐全且是整数；评分要点须按输入顺序逐条评价并提供依据。模型非法输出有限修复，失败仍作为模型失败处理，不冒充候选人答错。旧评分记录继续可读，新评分由代码标记 `prompt_version=v2`，重放旧评分不会误标成 v2。

回答正确且已覆盖题目要求时，不能因未讲题目未要求的拓展知识扣分。等价实现正常评价。反馈提供具体改进方向，不在继续追问前给出整套标准答案。

## 涉及文件

- `app/agents/prompt_policy.py`：策略版本及共享数据边界。
- `app/agents/parse_agent.py`、`question_agent.py`：解析、修复、出题提示词和生成校验。
- `app/agents/evaluate_agent.py`：评分尺度、严格新输出校验与唯一总分计算依据。
- `app/agents/followup_agent.py`：单方向追问、完整当前回答及关联上下文、独立要点生成。
- `app/schemas/evaluation.py`：新生成追问的契约，旧记录的读取契约保持兼容。
- `app/graph/state.py`、`nodes.py`：传递主问题上下文、独立评分要点。
- `app/services/recovery.py`、`interview_workflow.py`：历史问答重建、提示词版本落库。
- `app/agents/adapters.py`：Mock 输出同步遵循新契约。

数据库已有 JSON 评分要点字段，本轮不需要数据库迁移。对外题目仍过滤评分要点，报告聚合策略不变，主问题分数不会被补答覆盖。

## 验证

本地回归：276 项测试通过（包含 SQLite 流程、检查点恢复、模型异常与契约检查）。这不等于本轮连接真实 PostgreSQL/Redis 进行部署验证。

真实文字模型：`deepseek-chat`，8个合成评分样例各重复2次，另生成一条带独立要点的追问。固定样例和重跑入口为 `scripts/check_prompt_quality.py`：

```powershell
.venv/Scripts/python.exe backend/scripts/check_prompt_quality.py --live
```

该命令联网并产生模型费用；默认不带 `--live` 不执行。只传合成问答，不上传用户简历。人工预期范围在脚本中固定，结果在 `docs/prompt-v2-quality.json`。

| 样例 | 预期区间 | 两次实际分数 |
| --- | --- | --- |
| 正确且简短 | 85–100 | 87、89 |
| 解释充分 | 85–100 | 92、92 |
| 部分正确 | 35–75 | 44、36 |
| 核心错误 | 0–39 | 8、8 |
| 跑题 | 0–20 | 0、0 |
| 技术引用注入词 | 85–100 | 92、92 |
| 等价正确例子 | 85–100 | 90、90 |
| 狭窄追问独立评分 | 85–100 | 92、92 |

首轮抽查发现简短完整回答因未解释额外机制被打82分，详见 `prompt-v2-initial-quality.json`。因此补充“未要求的拓展不能扣分”后，使用相同样例和预期范围复查，上表16次均在预期范围。最大重复分差8分。

这是一组小样本冒烟检查，不是准确率或稳定性保证，也不是 v1/v2 的量化 A/B 对比。反馈中的扣分依据及追问语义仍需持续人工抽查，单个问号无法证明语义上只有一个任务。

另使用合成简历（Python/FastAPI 项目）和合成 JD（额外要求 Kafka）完成一次真实视觉模型解析、文字模型出3题。JD 的 Kafka 要求保留为独立 `source=jd` 依据，生成的 Kafka 能力题引用该依据，未预设候选人已有 Kafka 项目经历，3题类别均为技术类别。原始结构化结果见 `prompt-v2-materials-quality.json`。这是合成纯文字材料的验证，不能替代真实 PDF/图片版面识别评估。

## 使用边界

- 建议新建面试体验完整 v2：已生成的主问题和追问不重新出题，历史分数不重算；旧追问已经保存的主问题要点不会被静默改写。
- 已运行服务需要重启后加载新代码；本轮未操作用户正在运行的服务。
- 提示词版本集中在 `prompt_policy.py`。后续修改策略应同步更新版本，并用固定样例复查；已有 `提示词清单.md` 标记为 v1 历史快照。
